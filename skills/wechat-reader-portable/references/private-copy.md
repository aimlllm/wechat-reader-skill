# 首次取钥前：私有应用副本准备

只在本人尚无可用密钥且授权本机准备时读取。本仓库的 capture_filtered.py 不负责这些步骤，不保证它们在所有 macOS／微信版本可行。不得为了通过预检而降低身份、签名或 SIP 检查。

## 部署代理负责的准备

1. 检查正式微信当前完整路径、主进程、版本、完整签名和签名指纹；确认原账号历史正常。把这些必要信息留在仓库外的私有部署记录，不发送到 GitHub。
2. 核对保留一份完整原版应用备份。另做完整独立私有副本，保存在仓库外；不能使用会指回正式映像的软链接或硬链接来代替。不得修改、删除或替换聊天容器。
3. 审阅当前应用 entitlements 与捕获程序 preflight。该辅助程序要求私有副本只移除两项受限身份声明 com.apple.application-identifier 和 com.apple.developer.team-identifier，增加 com.apple.security.get-task-allow，并保留 sandbox、application-groups 和其他原有权限；正式签名保持不变，SIP开启。
4. 若本机系统允许且本人授权，对**副本顶层**准备上述可调试签名，去掉该副本顶层 Hardened Runtime，不递归重签内部 frameworks。不把 codesign --deep --sign 当默认修复，不重签正式应用。若版本需要额外变化，停止这一流程并说明不兼容，不擅自扩展修改。
5. 严格验证完整副本的签名、权限差异和独立映像；记录其实际 CDHash。分别核验查询工具、验证工具的签名与 SHA-256，准备捕获所需明确参数，不把新 hash 直接当成来源可信的证明。
6. 准备一次经允许的本机捕获入口和恢复步骤。本人只完成必须亲自进行的密码输入、手机确认或系统同意；这不替代动作许可。若捕获动作已被代理审核拒绝，停止并报告，不改成人工执行或换工具绕过。系统确实要求密码时，只在本机可信提示中输入，不进入聊天或配置。

本页故意不提供可盲贴的重签正式应用命令。应用签名、系统许可和版本差异需要部署代理在本机核对；复制应用、系统允许启动、能看到登录画面，都不是捕获可用的证明。

## 进入一次捕获

在相关动作允许的前提下，完全退出正式微信并核实进程停止。用明确完整路径启动私有副本，由本人确认停在原账号登录画面，暂不登录。代理不通过截图／OCR核对账号，不盲点UI；按[捕获参数与流程](acquisition.md)先做preflight-only，再进入有界捕获，Armed后本人登录及手机确认。

如果副本看到错误账号或历史缺失，不继续捕获，不新建或删除数据容器。若签名／启动／附加失败，保留固定错误分类在私有记录中，先诊断，不重复让本人退出账号。

## 结束与恢复

成功、失败或取消都要检查：调试器已经脱离并退出；私有副本完全退出；正式应用原签名仍匹配。然后恢复正式微信运行，核对实际主进程来自正式完整路径、原账号与历史正常。不得以界面标题、Dock 图标或进程名称代替路径核验。

若凭据已保存，仍需用 reader.py 对全部发现的数据库验证，并读取一个本人选定会话的真实消息。清理无法确认时单独报告，不能把捕获结果称为完整部署成功。
