# 备用读取路线

主查询失败时先保留错误类别、来源状态和覆盖信息在外部私有记录，再按实际阻塞选择路线。换工具不会自动补全电脑尚未同步的手机历史。

## 截图与 OCR

[wechat-summary](https://github.com/jackwener/wechat-summary) 使用 macOS 窗口导航、分页截图和 Vision OCR，减少对数据库加密格式的依赖。使用前审查固定提交的实际入口及依赖，并验证当前微信 UI、屏幕与辅助功能权限。项目可能包含发送、云端 AI 或 PDF 功能；本任务只选择经核实的本地捕获和 OCR 路径，不能直接运行整套默认流程。

先用少量合成或已授权内容检查：目标会话标题是否准确、截图是否覆盖完整气泡、上一页是否实际加载、语言识别和重叠去重是否正确。保留原图及识别结果在仓库外。相邻截图 hash 不变可能是加载未完成或翻页失败，不能单凭它断言到了历史顶部。

OCR 不提供数据库消息身份或完整性证明；发送人、时间、链接、重复文本和图片中的字需要核对。适合应急读取小范围可见历史，批量全历史搜索优先恢复 DB 读取。录屏交给云端模型前，另行确认用户已授权上传内容。

## Frida 作为有条件备用

Frida 能在已允许附加的目标上观察函数调用，但不天然获得更高权限。采用前审查源码和许可证，明确是系统函数符号还是微信私有地址／模式扫描；固定后者通常需要逐版本适配。

仅使用外部部署记录指定的私有副本和有限捕获范围。保留正式应用签名与 SIP，先验证目标身份、权限和退出恢复流程；不得自动注入正式应用、常驻拦截、规避保护或读取无关内存。若条件不满足，停止并保留诊断；不宣称某 Frida 文章在其他机器成功就能解决当前 attach 拒绝。

捕获值仍需逐库验证和私有文件保护。只读查询、重新取钥和注入器使用是不同操作，不能把“允许搜消息”推定为对后两项的无限授权。相关流程见 [acquisition.md](acquisition.md)。

## 固定输入：两种不同产物

| 产物 | 适用场景 | 保留与验证 |
| --- | --- | --- |
| 已解析原文归档 | 对已读取的有界内容反复总结、审稿、比对 | 记录时间窗、消息身份、解析警告和覆盖范围；固定后不自动更新，也不是可恢复微信备份 |
| 一致 SQLite 快照 | 需要重复分页、重新解码或离线查询 | 使用经过验证的 SQLite 备份／快照机制；处理 DB、WAL、SHM 关联状态并验证可读性，不在微信写入时只复制 `.db` |

两种产物都存仓库外。已解析归档无法找回未导出的字段或漏读消息；一致快照也只能覆盖取得时本机拥有的数据。恢复副本使用正确凭据验证，不直接在正式数据目录试验。

## 日报与旧项目

[ai-wechat-newsletter](https://github.com/LouYu2015/ai-wechat-newsletter) 是取到外部密钥后的日报层，不能解决无 `keys.json`。其 live 连接使用 `immutable=1` 的做法不照搬：SQLite 明确要求文件不会再变；把正在写入的微信库标为 immutable 会跳过变更检测，可能产生错误结果。日报成功生成也不证明所有分片、姓名和消息类型完整。[连接源码](https://github.com/LouYu2015/ai-wechat-newsletter/blob/main/wechat_daily/wechat_db.py)、[SQLite 语义](https://www.sqlite.org/uri.html)

`wechat-mac-reader` 的安装依赖与旧解密仓库有公开代码撤下、访问封锁的情况，先核实当前源码和构建产物是否仍在；历史分享不等于现在可安装。Chatlog Alpha 有迁移入口，应重新审查迁移源而非沿用旧功能列表。没有明确 macOS 实测证据的软件标为“Mac 兼容待验证”，不能以 Windows 成功替代。[路线比较与公开来源](comparison.md)
